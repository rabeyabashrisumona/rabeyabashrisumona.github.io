PlayVision — QA Automation Framework

A Playwright framework that tests a real e-commerce application at three layers: REST API, end-to-end user journeys, and visual regression.

Overview

Problem
Many test suites check only the user interface. Backend regressions and unintended visual changes can slip through when API behaviour and page appearance are not tested independently.
Approach
A single Playwright project with three independent suites — API, E2E functional and visual regression — built on the Page Object Model, with centralised test data and a GitHub Actions workflow.
My role and contribution
Designed and implemented the framework, page objects, test suites and CI workflow.
Technical stack
  • Playwright
  • JavaScript
  • Node.js
  • Page Object Model

Target application

The suites run against AutomationExercise.com, a public e-commerce site built for automation practice, with product listings, cart, checkout, registration and a public REST API.

Framework structure

UI interactions live in eight page classes (Login, Cart, Payment, Product, Category, Search, Contact Us, Checkout), so a change in the site's markup is fixed in one place rather than in every test. Test inputs are kept in a single test-data module, and credentials are read from environment variables that are not committed.

text
pages/            # Page Object Model — 8 classes
tests/
  api.spec.js             # API layer — 6 tests
  automation_e2e.spec.js  # E2E layer — 7 tests
  visual.spec.js          # Visual layer — 5 tests
testdata.js       # centralised test data
playwright.config.js
.github/workflows/playwright.yml

API testing strategy

API tests use Playwright's request context, so they run without a browser. They cover GET, POST and DELETE with both positive and negative cases.

  • List all products and all brands (200 + payload checks)
  • Search for a product, and search without the required parameter (400)
  • Unsupported DELETE method (405)
  • Register a new user with valid data

End-to-end workflows

  • Contact-form submission
  • Product search
  • Add to cart and remove from cart
  • Register → checkout → delete account, as a single journey
  • Invalid login shows an error (negative)
  • Checkout with an empty cart shows the empty state (negative)

Visual regression

Full-page screenshots of the home, products, login, cart and contact pages are compared pixel-by-pixel against stored baselines to catch layout shifts and missing elements that functional assertions would not notice.

CI/CD and reporting

A GitHub Actions workflow installs dependencies and browsers, runs the suite on every push to main and uploads Playwright's HTML report as a build artifact. Locally, the HTML report includes traces and videos for failed tests.

Run it locally

bash
git clone https://github.com/rabeyabashrisumona/playvision-qa-automation
cd playvision-qa-automation
npm install
npx playwright install
npx playwright test            # all suites
npx playwright show-report     # open the HTML report

Limitations

  • The pass count comes from a documented local run; it is not a measure of long-term stability across repeated runs.
  • Visual baselines are stored for Windows (Chromium and Firefox). Running the visual suite on another OS requires generating baselines for that platform.
  • Tests depend on a third-party practice site, so its availability and content changes can cause failures unrelated to the framework.
